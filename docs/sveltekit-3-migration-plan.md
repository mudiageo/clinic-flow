## Phase 1 — TypeScript config

### M1. Remove `rewriteRelativeImportExtensions`

- **Change** `tsconfig.json`: remove `"rewriteRelativeImportExtensions": true`.

### M2. Separate TypeScript project for the service worker

- **Change** move `src/service-worker.ts` → `src/service-worker/index.ts` (use `git mv`).
- **Change** the new `src/service-worker/index.ts` header:
  - Drop `/// <reference no-default-lib="true" />`, `lib="esnext"`, `lib="webworker"`, `types="@sveltejs/kit"`, and the relative `.svelte-kit/ambient.d.ts` reference (the new tsconfig supplies all of these).
  - Replace `declare let self: ServiceWorkerGlobalScope; self = globalThis.self ...` with `import { self } from '$app/service-worker';`.
  - Keep `import { BACKEND_HOST } from '$app/env/public';` — v3 explicitly supports env access in the service worker.
- **Change** create `src/service-worker/tsconfig.json`:
  ```json
  { "extends": "$app/tsconfig/service-worker" }
  ```
- **Change** root `tsconfig.json`: add `"exclude": ["src/service-worker"]`.
- **Tooling check:** SvelteKit 3 defaults `files.serviceWorker` to `src/service-worker` and resolves `index.ts`. The `SvelteKitPWA` `injectManifest` build consumes SvelteKit's compiled `output/client/service-worker.js`, so `vite.config.ts` must **not** be changed to `filename: 'index.ts'` (that would rename the emitted worker). `devOptions` is disabled, so the plugin's stale `srcDir/filename` defaults are inert.
- **Change** update the two `src/service-worker.ts` references in `sveltekit-tauri-remote-functions.md` to the new path.
- Add a dedicated check script (recommended): `"check:sw": "tsc -p src/service-worker/tsconfig.json --noEmit"`, and chain it from `check` so CI validates the worker project too.

### Additional finding: `src/lib/utils/server.ts` is now server-only

The v3 guide changed the server-only filename rule: a `server` path segment is enough (`server.ts`, `stuff.server.ts`), whereas `server.ts` was previously not server-only. `src/lib/utils/server.ts` is a browser-safe helper (`getServerUrl` reads `window.location`), imported by `src/routes/connect/+page.svelte`, so the production build failed with `server_only_import`.

- **Change:** renamed to `src/lib/utils/server-url.ts` (`git mv`) and updated the single import. The new name does not contain a bare `server` segment, so it is no longer treated as server-only.
